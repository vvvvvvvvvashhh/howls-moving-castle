# 《风起，城行》制作手记

这部一分钟短片跟着一只乌鸦走。它先带人绕过移动城堡的屋顶和城门，再把视线引到红屋顶小镇。观众在厨房见过卡西法，知道芜菁头右手托着谁，最后才有机会从高空发现草地上的两个小伙伴。四季交给剪辑，起飞、夜航和天亮则在同一个镜头里走完。[分镜与时间线](SHOT_LIST.zh-CN.md)

## 城堡怎样搭起来

远景里最容易认出城堡的，是朝前突出的船首、鼓起的锅炉、挤在一起的斜屋顶，以及底下四只张开的机械脚。门、桅顶和炉口各有空间坐标，镜头飞近时才能准确地找过去。造型参考了吉卜力公开的电影剧照，工程中的几何和表面纹理由程序构造。[吉卜力《哈尔的移动城堡》作品页](https://www.ghibli.jp/works/howl/) · [城堡模型](../src/castle.js)

| 部位 | 建模与运动 |
| --- | --- |
| 船腹和脸 | 沿截面铺弯曲铁板，叠出底部龙骨和船首护甲。两侧鼓起的锅炉嵌着圆形观察孔，中央炉口凹进船体，近看能看到开口的厚度。 |
| 屋顶和烟囱 | 木构小屋挤在锅炉上方，瓦片顺坡分行铺设，平台、梯子和外露管道把各层连接起来。高低错落的烟囱单独设转轴，脚一落重，管口还会晃几帧。 |
| 机械脚 | 每条腿有髋架、膝部活塞和跗节。足板分出三个前趾和后跟。脚落哪里先由步态决定，再反求各连杆的位置。蜷脚时，趾节和后跟各绕自己的铰链收起。 |
| 飞行机构 | 翼帆绷在可折叠的帆骨之间，布面在系点之间微微下垂。两侧各有张帆和受风的控制，船尾还有一对带活动桨叶的螺旋桨。 |

铆钉、铁板、窗框和瓦片的固定部分按表面材质合并成网格，关节、翼帆和会转动的轮盘单独保留。程序画出的铁锈、刮痕、木纹和灰泥使用固定随机种子。大块的明暗由船体形状承担，细纹留到掠过城门的近景再看。[建模和材质](../src/castle.js) · [翼帆与螺旋桨](../src/castle-flight.js)

## 从一脚着地到四脚离地

四只脚共用“已经走了多远”这个参数，各自错开落脚时间。标准步幅为 10.8 个场景单位，速度为每秒 2.25 个单位，实现一次完整循环约需 4.8 秒。单脚约 76.5% 的周期用于承重。这段时间，脚相对机身向后移动的距离抵消城堡向前走的距离，旁边的地面可以当尺子。抬脚前重量先落到另外三脚，落脚时锅炉才下沉、回弹。[步态计算](../src/locomotion.js) · [连杆与足板](../src/castle.js)

42 秒后步子越收越短，四只脚陆续找稳支点。锅炉下压的途中，靠镜头一侧的翼帆先在 43.02 秒张开，另一侧晚约八帧。锅炉总共约下压 3.28 个场景单位，最低处停约四帧。两侧阀门先后排汽，右前、左前、左后、右后足在 44.03–44.40 秒依次卸重。先让观众看见最后一只脚松开，再让视线追上抬高的机身。[起飞曲线](../direction/ending.js)

腾空以后，机身在 47.35、49.45、51.80 秒向两侧摆出三个幅度不同的峰。帆尖弯曲、悬足回荡，烟囱和桅杆稍晚才摆回。阀口的蒸汽向外散，脚边的尘土贴着地面扩开，屋檐抖落的碎屑往下掉。粒子按出生时的位置离开机体，因此城堡飞走后，尘土还留在后方。网页用点粒子表现这些短促的变化，Blender 另外生成带世界坐标轨迹的烟、尘、碎屑和火星。[网页尾声特效](../direction/companion-stage.js) · [Blender 粒子](../blender/motion/air_particles.py)

## 摄影机为什么慢几帧

如果把摄影机绑死在鸟身上，鸟一转弯，屋顶也会跟着猛甩。这里先画乌鸦的飞行路线，再给摄影机单独安排位置、注视点和视角。5.75 秒后，镜头开始采样最近 0.375 秒内的五个机位。位置和朝向的取样权重不同，观感约慢三四帧。贴近城门时收小延迟，给门框让出画面。进入小镇后，注视点从鸟身移向钟楼。任意拖回这段，同一时刻都从同一组历史位置计算。[鸟和摄影机的轨迹](../src/camera-b.js) · [跟拍的延迟](../direction/timeline.js)

30–40 秒用四个各 2.5 秒的外景走过一年。春天有开花的树和花瓣，夏天有湖湾和岸边的绿树，秋天有成片的金红树冠和落叶，冬天换成雪地与针叶树。网页里，屋顶和金属件朝上的部分也会积雪。切景时，城堡的步相和摄影机角度继续向前，观众可以一直盯着同一只脚。[季节场景](../src/journey-worlds.js) · [沿途植被](../src/journey-flora.js) · [城堡积雪](../src/castle-weather.js)

40 秒的交接点同时对齐上一段的机位、注视点和垂直视场角。摄影机接着从城堡一侧沿同一条弧线绕向正后方，机身受风甩动时，地平线只跟着轻摆。低处有沙丘、远处有城镇，云层从旁边移过，近处与远处的相对位移交代了摄影机的位置。天色经过浅蓝、橙灰、深蓝，日光和月光分别变化，星光与暖窗在暗处显出来。约 54.1 秒，太阳从城堡右侧的山脊露出，镜头接着俯向草地。[尾镜头轨迹](../direction/ending.js) · [日光、月光与窗光](../direction/sky.js)

## 火盆把两个场景接在一起

厨房里，卡西法先看向火盆，压低身子，从炉床跃出，落到两块劈柴之间。盆沿晃一下，火焰也随落地变扁。下一拍，芜菁头的右掌已经托住盆底。角色走多远、跳多高是一层动作，帽檐、衣摆和手腕又各有自己的反应。[厨房动作](../src/interior.js) · [芜菁头](../src/turnip.js) · [卡西法和火盆](../src/calcifer.js)

结尾要同时照顾上下两个主角。相机把对准桅顶和对准人物脚边的两条视线按比例混合，地上先露出帽尖，再看清整个人。火盆跟右掌走，火焰另有六次短跳，只给火苗加离盆高度。末尾城堡仍在低空向前飞，芜菁头在下方追，两者中间露出草地。[尾声构图和跳跃](../direction/ending.js) · [将动作施加到模型](../direction/apply-frame.js)

## 从 Three.js 到 Blender

| 阶段 | 工程里做了什么 |
| --- | --- |
| 1. 取出场景 | 在 Node 中求值程序化模型，导出网格、纹理、材质参数、实例变换与节点关系。按 24 帧/秒采样 60 秒，分别保存物体的位置、旋转、缩放、可见性和变形顶点。 [导出脚本](../blender/export/export_scene.cjs) |
| 2. 重建镜头和动作 | Three.js 用 Y 轴朝上，城堡前方是 +Z。相机位置和注视点都按 `(x, y, z) → (x, −z, y)` 转到 Blender。按垂直视场角换算 36 毫米宽感光面的焦距。对象运动写入动画曲线，部分逐帧网格变形压缩成可编辑的形态键。 [场景组装](../blender/render/scene_build.py) · [Blender 时间轴](../blender/render/timeline.py) |
| 3. 用两种渲染器表现同一段动作 | 浏览器以 Three.js r170 实时绘制，使用阴影贴图、FXAA 和 ACES Filmic 色调映射，支持拖动进度和绕城观察。Blender 4.3.2 通过 Cycles 计算材质、照明和阴影，另做草木、炉火、烟尘和薄雾。两端共用机位和动作节奏，逆光、薄雾边缘、草叶与火光的细节会各有差别。 [网页画面输出](../src/finish.js) · [Blender 动作与效果](../blender/motion/blender_motion.py) |

### 修改动作时从哪里入手

| 想改什么 | 改哪里，回看哪一段 |
| --- | --- |
| 城堡步幅 | `GAIT` 里的 `strideLength` 控制步幅，`stance` 控制单脚承重所占的比例。尾声的 `feetBefore` 用同一组数值停住最后一步，改步幅时一并调整。回看 40–44 秒的脚底和地面。 [步态](../src/locomotion.js) · [尾声站姿](../direction/ending.js) |
| 跟鸟的迟滞 | `sampleBirdCamera()` 里的 `delays` 是采样时差，`posWeights` 与 `dirWeights` 分别控制位移和转头。先看 9–11 秒转入俯冲，再看 13–15 秒门框是否留在画面里。 [跟鸟时间轴](../direction/timeline.js) |
| 展翼和扬尘的先后 | `rigAt()` 分别给两侧翼帆设置起止时间，`footTimes` 规定每只脚何时卸重。若重排四足，再对齐网页 `createTakeoffDust()` 与 Blender `_bursts()` 里的扬尘时点。 [机身和脚](../direction/ending.js) · [网页尘土](../direction/companion-stage.js) · [原生尘土](../blender/motion/air_particles.py) |
| 晨光出现位置与速度 | `sunAltitude` 管太阳高度，`sunAzimuth` 管方向，`sunDisc` 管日轮显露。`duringFlight` 同时写着天色、窗光与星光。调整后从夜色开始看至镜头俯向草地。 [尾声天空](../direction/sky.js) |

网页改完后，在仓库根目录运行 `npm run build`，再打开更新后的 `index.html`。手上有 `.blend` 时，可以直接在工程里改摄影机、灯光或动画曲线。要重新烘焙整段动作，再从 `blender/` 的制作源码入手。[网页入口与构建](../README.md) · [Blender 重建步骤](../blender/README.md)

## 减少细节闪动，保住炉火的颜色

早先的网页在 15.8–20.7 秒让阴影范围随摄影机平移，镇上的屋顶可能等到乌鸦飞近时才出现阴影。现在网页保留原有阳光的方向、色温和强度，用一张 2048 × 2048 的阴影贴图，从固定的正交机位一次覆盖城堡和镇区。逐帧检查开场 22 秒时，城堡和乌鸦始终位于投影范围内，镇上的 20 组网格也全部落在范围内，阴影投影矩阵在 528 帧间保持一致。[外景光和阴影范围](../src/atmosphere.js) · [网页播放时的场景更新](../src/main.js)

开场机位很低，细草、城堡漆面和远树的轮廓在相邻帧间容易跳。原生工程让六组近景草叶和野花使用带透明轮廓的漫反射材质，并在草地镜头提高透明光线反弹上限。最后一版又把基础采样设为 16，炉火室内（第 529–600 帧）和较暗的夜航至黎明（第 1189–1320 帧）设为 32。[草木材质](../blender/render/meadow.py) · [采样表](../blender/render/flicker_native_samples.json)

远景雾使用经过采样的 Mist 通道，并减去天空覆盖通道 `Direct sky coverage`。树梢和天空同占一个像素时，雾量会随覆盖比例变化。正常运动段的快门为 0.30 帧。切入厨房、户外和各季节时，切点前一帧与切入帧的快门归零，下一帧恢复，使前后两个场景各自有清楚的边界。[薄雾合成](../blender/render/flicker_native_master.py) · [快门关键帧](../blender/motion/finalize_project.py) · [Blender 4.3 渲染通道手册](https://docs.blender.org/manual/en/4.3/render/layers/passes.html)

制作记录在开场第 22–26 帧对比了旧方案（4 采样、按 Z 深度判断边缘）和新版（16 采样、按覆盖比例混合）。用相同的运动轨迹对齐局部画面后，近景草叶的亮度残差从 12.37 降到 5.87，城堡漆面从 4.48 降到 2.66，远树边缘从 5.88 降到 2.92。这组数值以 8 位亮度计，对应五帧的同一裁区，可用相同窗口复查改动。[局部时序对照](../blender/qa/flicker_motion/report.json)

原生输出为 1920 × 1080 的 RGB 8 位 PNG，已带 AgX 显示变换。合成视频时沿用原画面的 BT.709 亮度，色度最高增加约 8%。对炉火等接近色域边界的颜色，增幅会自动减小。网页则在绘图画布上应用 `saturate(1.08)`，界面文字保持自己的颜色。公开网页可以静音观看，也可以自行选择本地音频随画面播放。[原生视频调色](../blender/finish/color_finish.py) · [网页画布样式](../src/page.html) · [配乐与素材署名](ASSETS_AND_CREDITS.md)
